### `src/pages/TaskBoard.jsx`
**Complete rewrite — full claim/proof/status flow**

- Imports `useAuth` to read `profile.reward_points_total` for the live points banner (was hardcoded to 0)
- Task cards show a `LinearProgress` bar mapped to task status:
  - `available` → 0%, `claimed` → 40%, `pending_review` → 75%, `completed` → 100%
- Completed tasks rendered at 70% opacity with no hover lift
- `renderAction(task)` produces context-aware action UI per task:
  - **available** → "Claim Task" button (or "Login to Claim" if unauthenticated)
  - **claimed by me** → "Submit Proof" button (warning color)
  - **claimed by someone else** → locked chip
  - **pending_review by me** → "Awaiting Admin Review" chip (info color)
  - **pending_review by someone else** → disabled "Under Review" button
  - **completed** → "Completed" chip (success color)
- **Claim dialog**: confirmation modal with task title, description, and points reward; updates `status='claimed'`, `claimed_by=user.uid`, `claimed_at=now` with `.eq('status', 'available')` for concurrency safety
- **Proof dialog**: multiline textarea, updates `status='pending_review'` and `proof_text` with user's submission

### `src/pages/AdminPanel.jsx`
**Complete restructure — 4-tab layout**

Tab structure using MUI `<Tabs>` / `<Tab>`:

**Tab 0 — Site Settings**
- Unchanged from Phase 1: module enable/disable toggles persisted to `site_config` table

**Tab 1 — Users**
- Existing admin grant/revoke functionality from Phase 1 preserved
- Added BadgeIcon button per user row → opens **Membership Management** dialog:
  - `<Select>` for membership status (`Active`, `Expiring Soon`, `Expired`, `Pending Approval`)
  - Date input for `membership_expiry`
  - Saves to `profiles` table via Supabase update
- Self-protection: admin toggle and membership button are disabled for the logged-in admin's own row

**Tab 2 — Tasks**
- **Task Creation Form**: Title, Description, Points (number) → inserts new task with `status='available'`

  - **Approve**: sets `status='completed'`, increments `reward_points_total` on the claimer's profile by the task's points value
  - **Reject**: resets `status='available'`, clears `claimed_by`, `proof_text`, `claimed_at`

**Tab 3 — Announcements**
- Unchanged from Phase 1: compose form with optional image upload, published list with delete

## Required Database Schema Changes

Run the following SQL in your Supabase SQL editor before using the Task Board claim/proof features:

```sql
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS claimed_by TEXT;
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS proof_text TEXT;
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS claimed_at TIMESTAMPTZ;
```

These columns are needed by:
- `TaskBoard.jsx` — to set/read `claimed_by`, `claimed_at`, `proof_text`
- `AdminPanel.jsx` Tab 2 — to display proof text and claimer identity in the validation queue

## Known Limitations (Phase 3 scope)

- All admin checks remain **frontend-only** — the `is_admin` flag is read from Supabase `profiles` but Supabase RLS cannot enforce it server-side because Firebase Auth JWTs are not recognized by Supabase's `auth.uid()`.
- Phase 3 will address this via Supabase Edge Functions or a Firebase→Supabase JWT bridge with proper RLS policies.
